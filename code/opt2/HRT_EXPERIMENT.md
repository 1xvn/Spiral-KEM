# OPT2 HRT 메시지 인코딩 실험

이 실험은 `q=3329`, `n=256`인 Python OPT2에서 32바이트 메시지를 유지하면서 원래 HRT 투영을 사용할 수 있는지 비교한다. 기준 체크아웃은 `cbaf58de6d67178b1262156c7356f9cecb946956`이고, 독립 검토 대상은 연구 커밋 `488e98ac5aeccebd545949f971a4a1ca93ac0d9e`이다.

기존 OPT2는 메시지 비트를 바이트별 하위 비트부터 읽어 계수 중심 0과 1664에 놓는다. 역캡슐화는 `v − sᵀu`를 계산한 뒤 각 계수의 나머지 833~2496을 1로 읽는다. 복호한 메시지로 재암호화하고 16비트 직렬화로 암호문을 비교해 공유 키를 선택한다. [OPT2 구현](spiral_kem_toy_v031_opt2.py)

OPT2의 [SKW1](COMPACT_WIRE_SPEC.md)은 두 계수를 3바이트에 무손실 포장한다. `serialize_ciphertext_compact`와 `deserialize_ciphertext_compact`가 12비트 포장·해제를 담당한다. 기존 16비트 경로에는 같은 계수가 그대로 들어간다. [C KEM](../../native_research/spiral_native.c)도 `pack12` / `unpack12`와 기존 비트 중심을 사용하며, Rust 프로토콜은 [FFI](../../protocol_rust/src/ffi.rs)를 통해 C KEM을 호출한다. 후보의 인코딩·디코딩 오버라이드는 이 Python 실험에만 있다.

## 첫 후보의 투영 복호

`j=0…127`마다 원래 메시지의 비트 `j`를 기호의 하위 비트, `j+128`을 상위 비트로 둔다. 기호 `00, 01, 10, 11`의 중심은 각각 `0, 832, 1664, 2496`으로 정하고 계수쌍 `(j,j+128)`에 `(c,0)`을 넣는다. 관측 계수쌍 `(u,v)`는 `x = (u + 1729·v) mod 3329`로 투영한다. 각 중심의 비용은 다음과 같다.

```text
D(x,c) = min { max(|e_u|, |e_v|) :
               (c + e_u + 1729·e_v) mod 3329 = x }
```

오차의 최대 절댓값을 0부터 늘려 도달 가능한 나머지를 처음 방문할 때의 비용을 기록한다. 가장 낮은 비용의 기호를 고르고, 동점이면 숫자가 작은 기호를 선택한다. 전체 3,329개 나머지 가운데 두 기호의 동점이 **197개**다. 모든 나머지의 판정을 각 가능한 `e_v`와 그에 대응하는 최소 절댓값의 `e_u`를 사용하는 독립 계산으로 확인했다.

각 계수 오차가 `-6…6`이면 기호당 169개씩 총 **676개** 관측값이 모두 다르고 모두 원래 기호로 복호된다. 모든 계수쌍이 이 조건을 충족하면 32바이트 메시지 전체가 복호된다. 범위를 `-7…7`로 넓히면 `00 + (3,-6)`과 `01 + (-3,7)`이 모두 2945가 된다. 해당 나머지를 받으면 최소 비용 규칙이 `00`을 선택한다. 이 충돌 때문에 주어진 투영과 중심으로 반경 7 전체의 정확한 복호를 보장할 수 없다.

이 후보의 판독기는 두 계수 오차를 `e_u+1729·e_v mod 3329`라는 하나의 나머지로 받는다. 투영 뒤 관측값이 겹치면 판독기에 두 좌표를 이용해 원래 기호를 가려낼 정보가 없다. 실제 OPT2 오차로 시험했을 때 최대 절댓값은 75였고, 128,000쌍 중 115,376쌍이 반경 6을 넘었다. 1,000개 원문 모두에 반경을 넘은 쌍이 있었으며, 실제 판독 결과 1,000개 모두에서 하나 이상의 비트가 틀렸다. 반경 초과는 해당 쌍에서 복호 보장이 사라진다는 뜻이다. 표의 실패 수는 실제 판독에서 집계했다. ## 결합 후보 `--candidate combined`

착수 시 브랜치는 `research/opt2-hrt`, HEAD는 `cbaf58de6d67178b1262156c7356f9cecb946956`였다. 당시 작업 트리에는 수정된 `README.md`와 미추적 `HRT_EXPERIMENT.md`, `experiment_hrt.py`, `test_hrt.py`, `evidence/hrt_opt2_1000.json`이 있었다. 기존 투영 후보의 원본 JSON은 그대로 보존했고, SHA-256은 `bbb7916b0289dc58d92b25077667b23c90a3598dd6bc26999a99b1504f5d4806`이다.

`q=3329`, `n=256`에서 각 `j=0…127`에 대해 OPT2의 비트 `j`를 `a`, 비트 `j+128`을 `b`로 읽는다. 계수 `j`와 `j+128`에 각각 `x=1664a`와 `y=(1664b+800a) mod 3329`를 저장한다. 아래 기호는 `ab` 순서로 적는다.

| 기호 | 계수쌍 `(x,y)` | `(x+1729y) mod 3329` |
|---|---|---:|
| `00` | `(0,0)` | 0 |
| `01` | `(0,1664)` | 800 |
| `10` | `(1664,800)` | 0 |
| `11` | `(1664,2464)` | 800 |

`1729·1664 ≡ 800`이고 `1664+1729·800 ≡ 0`이므로 같은 1729 투영에서 `x+1729y ≡ 800b (mod 3329)`다. `b`는 투영값 0 또는 800에 해당하는 동치류를 고른다. `a`는 투영값을 보존하는 차이 `(1664,800)`만큼 이동해 같은 동치류 안의 서로 다른 두 대표 중 하나를 고른다.

결합 후보는 역캡슐화의 `v − sᵀu`가 만든 두 계수를 직접 읽는다. OPT2 판정으로 먼저 `a`를 읽고, 두 번째 계수에서 복호한 `a`에 따른 오프셋을 뺀 뒤 같은 판정으로 `b`를 읽는다. 이 방식은 원래 투영이 정의하는 동치류를 유지하면서 각 좌표의 복호 정보를 보존한다. 디코더는 두 비트를 원래 위치에 놓아 32바이트를 복원한다. 계수 판정표는 기존 OPT2 디코더에 3,329개 나머지를 넣어 생성한다. [결합 인코더·디코더](experiment_hrt.py#L137)

### 복호 성공 조건과 반경 증명

`D(t)`를 `t mod 3329`가 `833…2496`에 들면 1을 반환하는 OPT2 판정이라 하자. 같은 원문과 같은 모듈러 덧셈 오차 `(e_x,e_y)`를 주면 두 방식 모두 첫 비트로 `â=D(1664a+e_x)`를 얻는다. 기존 OPT2의 두 번째 판정은 `D(1664b+e_y)`다. 결합 후보의 두 번째 판정은 `D(1664b+e_y+800(a−â))`다.

- `â=a`이면 오프셋이 상쇄되어 두 방식의 두 번째 판정도 일치한다.
- `â≠a`이면 두 번째 판정은 달라질 수 있고, 둘 다 첫 비트가 틀려 원문 복원에 실패한다. 예를 들어 `00`에 `(833,833)`을 더하면 기존 OPT2는 `11`, 결합 후보는 `10`을 출력한다.

각 쌍의 성공 여부가 같으므로 128쌍을 모두 복원해야 하는 32바이트 메시지의 성공 여부도 같다. 이 결론은 같은 비트 배치와 판정 규칙을 사용하고, `v − sᵀu` 이후 위치별 모듈러 오차가 같다는 조건에서 성립한다. 오차의 독립성이나 분포 가정은 필요 없다. 독립 검토에서는 네 기호와 모든 모듈러 오차쌍 **44,328,964건**, 실제 32바이트 경로의 위치·경계 사례 **3,072건**으로 대조했다.

각 계수의 오차 절댓값이 831 이하이면 중심 0 주위의 나머지는 `0…831` 또는 `2498…3328`이고 중심 1664 주위는 `833…2495`다. 두 범위는 각각 `D=0`, `D=1`이므로 첫 비트가 맞고, 오프셋 상쇄 후 두 번째 비트도 맞는다. 실제 계수쌍 디코더로 기호당 `1663² = 2,765,569`가지, 총 **11,062,276가지**를 전수 확인했다. [반경 전수 검사](experiment_hrt.py#L182) · [HRT 회귀](test_hrt.py#L113)

반경 832에서는 `00+(0,+832)`와 `01+(0,-832)`가 모두 `(0,832)`에 도달한다. 현재 디코더는 이 관측을 `00`으로 읽는다. 고정된 조건에서 디코더가 정렬된 256개 나머지만 보고, 256비트 메시지를 모두 지원하며, 각 좌표의 `−832…832` 오차 조합을 전부 허용한다고 하자. 메시지마다 `1665^256`개의 서로 다른 관측을 갖는다. 항상 복원하려면 메시지별 집합들이 서로소여야 하므로 `2^256 × 1665^256 = 3330^256`개의 관측이 필요하다. 가용 공간은 `3329^256`이므로 이 모델에서 가능한 최대 정수 보장 반경은 **831**이다.

## 공개 fixture 1,000회 관측

각 후보를 기존 OPT2와 같은 공개 SHAKE256 fixture 1,000개로 짝지어 비교했다. 회차마다 하나의 키쌍과 동일한 메시지를 두 인코딩에 제공했다. 기존 `encapsulate`가 파생한 난수를 공유한다는 점을 두 암호문의 `u`와 복호 직전 계수 오차로 대조했다. 검토 대상 커밋의 실행기는 각 암호문을 SKW1과 레거시 형식으로 직렬화하고, 두 형식에서 파싱한 객체 각각에 `decapsulate`를 실행한다. 복원한 `u,v`와 두 역캡슐화 반환값의 일치를 확인한 뒤, 해당 인코딩의 송신 키와 비교해 회차별로 한 번 집계한다. [측정 코드](experiment_hrt.py#L231)

| 항목 | 기존 OPT2 | 첫 HRT 후보 | OPT2+HRT 결합 후보 |

| 32바이트 메시지 복호 실패 | 0 / 1,000 | 1,000 / 1,000 | 0 / 1,000 |

기존 OPT2 열은 두 비교에서 같은 결과를 냈다. 결합 후보는 기존 OPT2와 1,000회 모두 서로 다른 암호문을 생성했다. 결합 후보의 128,000개 계수쌍 중 반경 831을 넘은 쌍은 0개였다. 계수 오차는 `v − sᵀu`에서 원래 인코딩 계수를 뺀 뒤 `[-1664,1664]`의 대표로 환산했다. 표의 수치는 공개 fixture에서의 관측이며, 반경 831은 위에서 증명한 모든 해당 오차 벡터에 대한 보장이다. ## 재현과 근거

연구 커밋을 체크아웃한 뒤 저장소 루트에서 Python 3.10 이상으로 실행한다. 새 디렉터리에 출력해 원본 JSON을 보존한다. 첫 후보 원본 JSON의 명령은 기본 모드를 사용해 `--candidate projection`을 생략했다.

```bash
python3 -B -m unittest discover -s code/opt2 -p test_hrt.py -v
python3 -B code/opt2/verify_opt2.py
python3 -B code/opt2/verify_equivalence.py
out=$(mktemp -d)
python3 -B code/opt2/experiment_hrt.py --candidate projection --trials 1000 --output "$out/hrt_opt2_1000.json"
python3 -B code/opt2/experiment_hrt.py --candidate combined --trials 1000 --output "$out/hrt_opt2_combined_1000.json"
printf '%s\n' "$out"
```

2026-11-26 독립 검토에서 HRT 회귀 10개, `verify_opt2.py`, `verify_equivalence.py`, 결합 후보 1,000회 재실행이 모두 종료 코드 0이었다. 문서 마무리 과정에서 두 후보의 1,000회 실행을 각각 반복해 종료 코드 0과 원본에 공통으로 기록된 수학 검사·측정값의 일치를 확인했다. 결합 후보의 소스 해시도 일치했다. 보존 JSON은 연구 커밋을 만들기 전 작업 트리에서 생성됐다. 첫 후보 원본 JSON에는 당시 실행기의 소스 해시가 들어 있다. 표의 첫 후보 최대 오차는 원본의 `max_pair_error`와 재실행 결과로 확인했다.

## 호환성과 채택 조건

두 직렬화 형식은 계수를 무손실로 보존하고 인코딩 모드를 식별하는 필드를 두지 않는다. 같은 포맷으로 파싱되더라도 양쪽이 서로 다른 인코딩을 고르면 메시지 판정과 재암호화가 달라져 역캡슐화 시 대체 키가 반환될 수 있다. 혼합 운용을 검토할 때는 양쪽이 같은 코덱을 선택하도록 프로파일을 구성하거나 모드 식별과 버전 정책을 정의한 뒤 교차 모드 동작을 검증해야 한다. [SKW1 형식](COMPACT_WIRE_SPEC.md) · [역캡슐화](spiral_kem_toy_v031_opt2.py#L216)

독립 검토에서는 메모리에서 레거시 역캡슐화 호출과 반환값 비교를 제거해도 `test_paired_wire_and_full_message_metrics`가 통과함을 확인했다. 보고 필드 `wire_formats_decapsulated_per_encoding`은 고정 목록이며, 크기 집계는 직렬화 왕복만으로 채워진다. 채택 전 회귀는 두 파서가 반환한 객체가 각각 실제 역캡슐화에 전달되는지 확인해야 한다. [역캡슐화 호출](experiment_hrt.py#L238) · [보고 필드](experiment_hrt.py#L316) · [회귀 시험](test_hrt.py#L127)

현재 결과는 원래 투영의 구조를 보존하면서 기존 OPT2와 같은 복호 성공 조건을 얻을 수 있음을 보여 준다. 채택 판단에는 그 구조를 사용하는 구체적 이점, 암호 설계에 대한 독립 검토, 적용 환경의 희귀 복호 실패 추정, 대상 구현에서의 성능과 상호운용 검증이 필요하다.
